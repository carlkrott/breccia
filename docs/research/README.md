# Paired research (standing rotation)

Every implementation / test round is paired with **one research subagent** that does two things:

1. **Vulkan capability audit** — anything in the driver/extension/parameter surface we are not exploiting, tied to a current bottleneck.
2. **One engine audit** — a single inference engine (not yet covered) reviewed for workflows, methods and specific advantages we have not tried, with an adaptation sketch for our Vulkan engine.

Findings land in `docs/research/NN-<engine>.md`. This index tracks coverage so we never re-audit the same engine twice.

Round verdicts (one line each, so a future round knows what was learned without re-reading):

* **36 — Niche Vulkan engines: no weight paging fits the 30 GiB cap, and two-stream `--gpu-experts auto` in `bench token` and `bench agents` silently runs zero resident blocks.** MNN's Vulkan path keeps weights resident and declines int2 and int3, and its mmap is plain MAP_SHARED paging. Fastllm has an O_DIRECT bounded disk-expert cache; its miss-only variant is card B, which conflicts with doc 03 §A.3 and needs owner sign-off. Under uniform routing the misses are 46.44 MB per stream-token, 16.0% to 16.5% of the device ceiling at the two-stream aggregate in the engine comment (derived). Flag-OFF `auto` streams all 48 blocks: +162.56 MB per stream-token (+24.06%) and 9.97 GiB over the cap against the nine-block default (derived). WebGPU and wgpu add no card. Ranked flag-OFF cards: A, C, B. Gain: UNVERIFIED - requires the GPU qualification card
* **35 — Tiered expert cache and cross-stream dedup: the 30 GiB cap binds under uniform routing (decode skew unmeasured), the page hint is clamped, and cross-stream dedup is small.** Under uniform routing the cap misses 6.87% of references (a bound, 46.4 MB per stream-token); one prefill point implies an 8.18 GiB window, inside the cap, but decode skew is unmeasured. Each WILLNEED reads at least 128 KiB (0.04% to 0.71% of the named bytes), so the hint is ineffective, and DONTNEED drops nothing while the pages are mapped. Cross-stream dedup saves 0.98% of pair bytes under independent routing, and the page cache already shares the disk reads. Residency +4 blocks (C2) is the only lever that fits under uniform routing (0.28 GiB spare at zero headroom; VRAM unmeasured). Ranked flag-OFF cards C1 to C6 are in `35-tiered-expert-cache-and-cross-stream-dedup.md` section 6. Gain: UNVERIFIED - requires the GPU qualification card
* **34 — Long-context KV retention and eviction: bytes per cell set the ceiling, and only context shift bounds positions.** The q8-V layout is 20,736 B per cell over 12 QSA blocks, so a full 100K cache needs 2 displaced blocks on RX or 3 on MI50, and 256K needs 6 on both (single-card estimate; UNVERIFIED for the split placement the 930 MiB comes from). Sink plus a 4,096-cell window (4,112 cells) saves 95.9% at 100K with pooled keys remapped to retained cells (85.3 MB), or 88.8% with today's buffer sizing (232.6 MB, pooled keys sized by length); it keeps absolute positions, so it still hits max_pos; llama.cpp-style context shift is the only card that bounds positions. Placement charges f16-V bytes (2,180 B per cell-layer) whatever `BRECCIA_KV_Q8V` is, a 26.2% over-charge at q8-V. Counted eviction work is open or closed unmerged (vLLM #43374 and #53871, SGLang #33856, llama.cpp #27583); H2O, Quest and DuoAttention are title-only PR-search negatives. Ranked flag-OFF cards: C1 sink/window, C3 context shift, C5 Quest bounds, C2 H2O, C4 PyramidKV. Gain: UNVERIFIED - requires the GPU qualification card
* **33 — GDN chunkwise prefill and long context: chunking is a small lever.** The GDN scan is 2.86 ms of a 155 ms prefill token (about 1.8%, probe-derived, Gate 0 checks it) and the whole GDN sublayer is at most 5.7%. Long context at 100K is set by KV bytes and displaced arena blocks, not by GDN state (RX needs about three displaced blocks at two streams, extrapolated). Ranked flag-OFF cards: register-resident state column (`BRECCIA_GDN_COLREG`, first, because it tests the traffic model), T-row dispatch, batched projections, WY/UT chunk form, chunk-boundary snapshots; the reverted 32-lane variant stays reverted.
* **32 — Heterogeneous GPU balance and batch determinism: no shared-state mechanism is proven as the divergence cause, and the decode pool is 32 threads, not the 16 some comments say.** Heterogeneous serving systems split layers or requests across unequal GPUs and need per-layer exchange, which one-device-per-stream avoids. Ranked levers are capped by RX busy time (53–62 ms per step). An RX copy of host-lane experts loses to the host lane at the 32-thread default (0.69 vs 0.53 ms per block-token, `UNVERIFIED - requires the GPU qualification card`) and only ties at 16 threads (0.71 vs 0.69). The top estimate, a third stream on the RX, gives 24–28 tok/s (`UNVERIFIED - requires the GPU qualification card`); it needs a shared-model check, and a measured 4–6 stream plateau of about 25 tok/s is a risk. Overlapping the host lane with the fence (25–28 tok/s, `UNVERIFIED - requires the GPU qualification card`) needs a second host lane thread that doc 28 rejects unless the pool is split, so it is held. The first determinism test matches residency between single- and two-stream runs; global batch counts and cross-device DIRTY state are candidates, not findings. Six flag-OFF cards in `docs/research/32-hetero-gpu-balance-and-determinism.md`.
* **31 — Host memory tier: what the lane's mapping can and cannot get.** The mapping has no memory-tier advice, and THP does not reach it (FilePmdMapped 0). At 18 host blocks the 15 GiB set fits under the 30 GiB cap before PLE pages; at 39 it is 2.5 GiB over, so 41 ms needs about 2.5 GB/s of steady-state storage misses. Gate 0 comes first: extend doc 30's output with cgroup, smaps and perf counters. Card 1 (MADV_RANDOM on the PLE table only) is the lead card; its 2 MiB read-around bound is capped by the kernel's miss throttle. Hugepage import (card 6) waits on an unverified ANONONLY check.
* **30 — CPU low-bit expert kernels: what reaches the host lane.** Gate 0 comes first: residency, read_bytes and `--threads 32` in one output, since the lane fell from 85.7 to 41.2 ms/step between 8 and 32 threads (phase-4 §8y). Step model, derived and checked against §8y: pair step ≈ lane + fence + 18 ms. T-MAC and BitNet LUTs are rejected (a 10 MiB f32 table against 1 MiB L2, and ternary weights); llamafile mixmul is a grouping pattern, not a kernel; single-limb int8 fails 1e-5 on 94–99% of synthetic rows. Cards 0–7 as numbered in the doc: card 0 Gate 0, no code; card 1 16-thread per-CCD probe; card 2 AVX-512 f32 decode; card 3 in-block expert prefetch; card 4 two-limb VNNI int8, end-to-end gated (Gaussian synthetic passes, outlier synthetic 0.4% of rows over 1e-5); card 5 prefill gate/up `_many` for IQ2/IQ3; card 6 per-CCD pinning, low prior (doc 08 §6.3); card 7 two-row register blocking. Doc: `30-cpu-lowbit-expert-kernels.md`.
* **29 — Model loading and checkpoint I/O: what ports to Breccia's loader.** No new loader is needed. Gate 0 comes first: the page cache may hold the arena's 26.7 GiB source pages plus the 14.99 GiB streamed set (41.69 GiB against a ~30 GB host budget, derived), and residency is not measured. Ranked: (1) drop the arena's source pages after upload and hint the expert ranges, no format change; (2) mlock the 14.99 GiB streamed set on the file mapping, not an anonymous copy, accepted on major faults and MemAvailable; (3) cold start only: O_DIRECT, page-multiple, chunked reads with a queue-depth sweep (QD 8 is the NVMe knee, a prior only; no SATA sweep exists), gated on the owner's weights-volume decision, and new code since the engine has no such read path; (4) a frequency-ranked expert sidecar, only if (2) cannot hold the set and a routing histogram shows skew, since the routing evidence conflicts; (5) RX-only zero-copy host-imported arena, a doc 27 gate. Rejected: GPUDirect Storage (cuFile needs CUDA; Breccia's device path is Vulkan, with no HIP runtime), ServerlessLLM's format and tiers (would rewrite shards), fastsafetensors tensor-parallel sharding, per-expert O_DIRECT from the GGUF. The three designs were pinned and read at file:line; their speed claims are `UNVERIFIED - requires the GPU qualification card`. Doc: `29-model-loading-and-checkpoint-io.md`.
* **28 — IREE and Kompute async submission: what reaches Breccia's fence waits.** Gate 0 comes first: on the code path, the brief's `shared-exp` figure is a timer attribution, not a fence in stream A's own shared expert. The stream's SHARED mark (`graph.rs:2039`) runs until its next WAIT_GPU mark (`graph.rs:3001`), so the peer stream's fence wait, lane and submit land in it (`multi.rs:192-208`). Ranked: (1) Card 1, a Timers re-anchor in `Multi` (measurement only; accept when per-stream SHARED is at most 0.2 ms/token and the discarded gap matches the peer's `t_finish` plus `t_submit` within 5%). * **25 — EXL3/QTIP trellis and KV/state quantization. q8_0 = 0.32× attention time (11.7 → 3.8 ms/token measured) and 5.4e-3 dot error, q4_0 = 0.18× and 9.3e-2 error (cos 0.9956), rotation **unverified** for this model — so q8_0 default, q4 behind a gate, and it is what turns 1–2 slots into 5–7. **ggml-vulkan** (clone OK, `7aca0d2`) ships "tensors in system RAM, computed on the GPU" as `GGML_VK_PREFER_HOST_MEMORY`/`ALLOW_SYSMEM_FALLBACK` — the capability §A1 prices — but its MoE offload (`-cmoe`/`-ot`) is **CPU GEMM**, the same lane we have, so the host-resident-expert pattern is validated by them and *unclaimed* by them; * **07 — attribution tooling priced, and the §8ac mystery is a boundary cost.** On this box there is **no hardware-counter and no profiler path**: `VK_KHR_performance_query` is advertised with **17 counters on qf0 only** (0 on the dedicated compute family) but `vkCmdBeginQuery` on a performance pool **segfaults in `libvulkan_radeon.so`** (mesa 26.2.4, reproduced from raw C and from ash; box healthy), and **RGP is impossible** (0 `rgp` symbols in `/proc/kallsyms`, no `/dev/rgp`); `umr`/`radeontop`/`amdtop`/`perf` are not installed (`perf_event_paranoid=2`, passwordless sudo available). * **02 — measured follow-ups + PowerInfer.** Barriers are **free as packets** (0.01 µs); what costs 1.1–4.4 µs/dispatch is the *launch serialization* they force, so `full→sync2` is worth **−2.5…−6.2 ms/token** and nothing more — the 21–29 ms attribution of round 1 is **refuted**, and event-based waits, wave32 (0.1 % on a latency probe), the transfer queue as a global flag (8.6× *slower* for on-card copies on the MI50) and denormal modes all measured ≈0 or negative. * **03 — IO/page-cache + exllamav2.** The model-bigger-than-RAM problem is **one sysctl, mis-set**: `read_ahead_kb` must be written to the **btrfs BDI** (`/sys/class/bdi/btrfs-1/`), not the block device's queue (writing the latter changes nothing), and 8192 → **128 KiB** takes cold expert reads from **0.7–1.1 to 4.7–5.4 GB/s** with amplification **9× → 1.05×** — i.e. a cold run 28 → 4 s and the merged-prefill byte floor from 21 to ~140 tok/s/agent. With that right, `O_DIRECT` (5.9 GB/s cold but 10× worse than the 58 GB/s warm page-cache path), `FADV_RANDOM`/`MADV_RANDOM` (llama.cpp's env knobs: neutral-to-*negative* on btrfs and on 462–900 KiB regions), `MADV_SEQUENTIAL`, prefetch depth > 2 (queue-limited: `nr_requests 256 × max_sectors 128 KiB = 32 MiB` ≈ 1.7 blocks) and `MADV_POPULATE_READ` (3.9 GB/s, blocking) are all dominated. The PLE shard is a *different* pathology: one 28.8 GiB tensor of **90-byte records**, 65 µs per cold row, 48× btrfs-extent over-read, 0.5 µs warm — residency + 32-way parallel gather, not advice. exllamav2 contributes exactly two things: the **measure-per-module-then-anneal-the-bit-budget** allocation method (only usable for KV — our weights are a fixed artifact behind a bit-identical gate) and the structural fact that its per-layer launch count is **~2 against our ~31**, whose Vulkan form is **`vkCmdDispatchIndirect` over a pre-recorded command buffer** (a replayable "graph" without the 6-deep ring) on top of the fused MoE already queued as item 7. Its CUDA graphs, fp8 KV and `bits_prop` mixed-rate format have no Vulkan equivalent and matter little.
* **04 — launch count, priced + LMDeploy/TurboMind.** The launch-count gap is **not a launch problem**: a dispatch with nothing to wait on costs **0.007 µs (RX) / 0.031 µs (MI50)** of GPU timeline, but one compute→compute barrier after each costs **0.650 / 2.867 µs**, and `dispatch_batch::record` emits exactly one barrier per dispatch — so our 1 509 dispatches/token buy **0.98 ms (RX) / 4.32 ms (MI50)** of serialisation = 1.4–6.1 % of the 70.8 ms GPU half, and **round 3's headline `vkCmdDispatchIndirect` is refuted**: indirect costs **+0.77 µs (RX) / +1.65 µs (MI50)** per dispatch (1.418 vs 0.650; 4.510 vs 2.867), i.e. −1.2…−2.5 ms/token if adopted. * **05 — PLE gather/IO priced + TensorRT-LLM.** For 90-byte records, **`vkCmdCopyBuffer2` region arrays are the worst option measured**: **~300–360 ns/region (MI50) / 110–140 ns (RX)**, nearly independent of region size (6 144 rows = 2 316 µs / 857 µs), because the copy engine serialises one packet per region — the "batch the small copies" instinct is 40–350× *slower* than a compute shader. A **compute-shader gather costs load-instruction count, not bytes**: 45 × `uint16` (byte-exact 90 B) = **7.4 ns/row (MI50) / 2.3 ns/row (RX)**; the same data **padded to 96 B and read as 6 × `uvec4`** = **1.0 / 0.34 ns/row (77 / 234 GB/s payload)** — **7.4×/6.8× for +6.7 % storage**, and wider ILP does not help. Where the source lives dominates: VRAM 1–3 ns/row, but **system RAM over PCIe 46.9 / 64.6 ns/row** — *and `HOST_VISIBLE|DEVICE_LOCAL` "ReBAR" is VRAM, not host memory*, which invalidates the obvious version of that experiment; a warm 32-thread host gather (~16 ns/row amortised) beats GPU-over-PCIe, so the GPU may only gather what is already local. Plus `SpeculationGate` (rolling accept-rate → permanent disable, ~20 lines) to ship with any future draft path.
* **06 — small-M GEMM shapes priced + ncnn.** Launch *geometry* is not a lever: 64→512 threads (2→16 rows/WG) is flat within **5 %** on both cards for the shared expert's two shapes, so the current `ls256/r8` stays and the chunked pass must not be re-tuned around launch shape; the only cheap win is **`UNROLL=2` on the block loop (−9 % gate/up m=1, −8 % m=8, −9 % down m=1, neutral-to-worse at `bpr=3`)**. **LDS staging of the activation rows is a loss everywhere (+6 %…2.6×)**. Two measurement traps set the prices honestly: an un-warmed first dispatch reads **5× slow** (2.39 µs vs 12.4 µs for the same 640×2560 m=1 GEMM), and 64 back-to-back identical dispatches **overlap** (137 ns) where a *dependent* chain pays **1.07 µs per barrier** (v2 `COMPUTE→COMPUTE` is 1.6× cheaper than our v1 `ALL_COMMANDS`; `write→read` == `read|write`; `BY_REGION` −4 %), so the parked pruning item is worth **−1.0 ms/token** at 1509 → ~400 barriers — and ncnn's **per-resource tracked `stage`/`access` flags** (`command.cpp:2214`) is the pattern that removes the call-site ≠ dispatch blocker. **gate+up+SwiGLU fused into one dispatch is the round's biggest win: 15.6 → 4.7–5.0 µs (m=1) and 50.7 → 9.3 µs (m=8), 3.1×/5.3× on the dependent path**, because a dependent GEMM costs 5.35 µs as a chain leg but 2.79 µs back-to-back; **SwiGLU+`down` in one dispatch is infeasible** (needs all 1.84 MB through one CU; Vulkan has no grid sync), so "chunk-level" means 2 dispatches, not 1. At m=8 the shared expert's three GEMMs are **18.8 µs/block = 0.90 ms/token over 48 blocks** against ~5.8 ms/token in the T=1 trace — the rest is dependency structure, not kernel time. **`VK_KHR_cooperative_matrix` is absent on both cards** (settles round 1), the RX's default subgroup **is 64** (forcing 32 costs 5–8 %), the MI50 is **3.0–5.2× slower** on exactly these shapes, and the untried features that matter are **shape-specialised pipelines** (ncnn freezes shape + `local_size` per pipeline and persists the cache — our unroll-2 win is its floor), **`VK_KHR_pipeline_binary`** (kills the cold-start compile behind both the 5× trap and the 24-fresh-shapes reset), and **`VK_EXT_descriptor_buffer`**. ncnn's mobile baggage — storage images, `elempack`, winograd, and the Adreno-bug workarounds sprinkled through `convolution_vulkan.cpp` — does not transfer. **Reprice one number (`06a`, second independent harness, IQ4_XS):** the dependent-chain barrier cost is **flat from 1 to 320 workgroups** and tracks **`bpr`** instead (1.15 µs + ≈0.45 µs per dependent block ⇒ `bpr` 2/3/10 = 1.6/2.5/5.6 µs), so it is **cache invalidation, not wave-drain**, and a pruned `bpr=10` barrier is worth **≈5.6 µs, i.e. ≈−4.5 ms/token at 1509 → ~400** (not −1.0); barrier *form* (sync2 vs `ALL_COMMANDS`) measured identical on both harnesses' working sets, so narrow the masks for hygiene, not for milliseconds.
